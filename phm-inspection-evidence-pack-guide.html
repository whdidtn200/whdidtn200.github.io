PHM Inspection Evidence Pack Guide

점검 티켓이 열렸는데도 학습 가능한 운영 기록이 남지 않으면, false positive를 줄여도 같은 논쟁이 반복됩니다. 이 가이드는 경보부터 종결까지 무엇을 한 묶음으로 남겨야 하는지 정리합니다.

Updated 2026-07-21Field RecordsInspection TicketClosure Label

핵심: 좋은 evidence pack은 왜 열렸는가, 무엇을 봤는가, 무엇을 했는가, 무엇으로 닫았는가를 같은 사건 안에 묶습니다. 그래야 threshold 조정, sensor health 개선, 모델 재학습이 모두 같은 기록을 참조할 수 있습니다.

evidence pack의 여섯 조각

1. Trigger snapshotscore, threshold, severity, persistence 결과
2. Context snapshot속도, 하중, mode, 정비 상태, sensor health
3. Signal excerpt파형, 스펙트럼, 추세, baseline 비교
4. Field proof사진, 메모, 냄새, 소리, 마모 흔적
5. Action record작업 지시, 교체 부품, 재가동 조건
6. Closure labeltrue positive, false positive, inconclusive, sensor issue

티켓 상단에 반드시 보여야 할 것

  • alert_id, 자산·부품·센서, 발생 시각
  • 모델 버전, feature 버전, threshold 버전
  • 점수 단독인지 evidence bundle인지, 어떤 persistence rule이 적용됐는지
  • 최근 24시간 반복 경보 여부와 최근 정비 이력
  • 센서 health, 최근 캘리브레이션, 통신 이상 여부

첫 화면만 보고도 현장 담당자가 이번 경보가 이전과 무엇이 다른지 알 수 있어야 합니다.

파형과 특징은 어떻게 붙일까

신호를 전부 덤프하는 것은 evidence pack이 아닙니다. 대표 파형, 지난 7일 baseline 대비 추세, 동일 조건 healthy 구간과의 비교, sensor health 상태 네 장이면 대부분의 초기 판단이 가능합니다.

그래프는 많을수록 좋은 것이 아니라, 경보가 열린 이유와 현장 점검 방향을 좁혀 주는 순서로 있어야 합니다.

사진과 현장 메모가 중요한 이유

같은 vibration anomaly라도 실제 원인은 윤활 부족, 체결 느슨함, 센서 고정 불량, 외부 충격, 운전 조건 변화일 수 있습니다. 숫자만으로 닫히지 않는 차이를 현장 사진과 짧은 메모가 메워 줍니다.

  • 설치 상태와 배선 상태를 보여주는 넓은 사진
  • 의심 부위를 가까이서 보여주는 근접 사진
  • 조치 후 재조립 상태를 보여주는 완료 사진

evidence bundle 실험이 주는 시사점

MALT의 공개 실험에서는 score 하나보다 score + diff_rms, score + diff_rms + kurtosis처럼 서로 다른 증거를 묶은 정책이 복합 조건의 nuisance burden을 줄일 가능성을 보였습니다. 점검 티켓도 마찬가지로, 어떤 증거 묶음으로 열렸는지 자체를 기록해야 합니다.

파형 하나만 남기지 말고 context와 field proof를 같이 저장해야 나중에 모델이 아니라 운영 규칙을 먼저 고쳐야 하는지 판단할 수 있습니다.

종결 label은 반드시 강제하라

Label의미다음 액션
true_positive실제 이상 또는 열화 징후 확인정책 유지 또는 조기화 검토
false_positive이상 없음, 불필요 경보threshold/persistence/bundle 재검토
inconclusive충분한 근거 없이 종료추가 계측 또는 재관찰
sensor_issue센서/배선/수집 문제sensor health와 설치 품질 개선

자유 메모는 label 뒤에 붙여야 합니다. label이 먼저 있어야 주간 리뷰와 재학습 전 필터링이 가능합니다.

보존 기간과 링크 구조도 설계해야 한다

evidence pack은 작성하는 순간만 중요한 것이 아닙니다. 최소한 경보 원문, 대표 그래프, 현장 사진, 작업 결과, 종결 label이 같은 alert_id로 다시 찾아져야 합니다. 파일 서버, CMMS, 메신저, 이메일에 증거가 흩어져 있으면 다음 threshold 리뷰 때 다시 수작업으로 모아야 합니다.

가장 단순한 원칙은 한 경보, 한 사건, 한 링크입니다. 경보 페이지 하나에서 관련 그래프, 사진, 작업 지시, 종결 메모로 모두 이동할 수 있어야 하고, 반대로 작업 지시에서도 원래 경보와 baseline 비교 그래프로 돌아올 수 있어야 합니다. 이 연결성 자체가 운영 자산입니다.

주간 리뷰에서 evidence pack을 쓰는 법

주간 리뷰에서는 모델 정확도보다 evidence pack이 비어 있는 티켓을 먼저 봅니다. 파형이 없는 경보, 종결 label이 없는 티켓, 사진이 없는 true positive는 다음 주 개선 우선순위입니다.

  • 어떤 evidence bundle이 실제 점검 전환율을 높였는가
  • 어떤 sensor issue가 경보 품질을 가장 많이 해쳤는가
  • 어떤 라벨이 과도하게 inconclusive에 몰렸는가
  • 다음 주에 비워둘 수 없는 evidence field가 무엇인가

30일 도입 순서

첫 2주에는 label 강제와 대표 그래프 2장, 사진 2장만 의무화합니다. 3주차에는 model/threshold/persistence 버전을 티켓 상단에 노출합니다. 4주차에는 CMMS와 연동해 작업 결과와 closure label이 자동으로 다시 경보 기록으로 돌아오게 만듭니다.

처음부터 모든 사진과 모든 파형을 강제하면 현장만 피로해집니다. 핵심은 다시 판단할 수 있는 최소 증거 묶음을 먼저 표준화하는 것입니다.

한계와 적용 범위

이 가이드는 특정 CMMS 제품이나 철도 운영사의 승인 체계를 대체하지 않습니다. 다만 어떤 시스템을 쓰든 evidence pack 구조는 별도로 설계해야 하며, 그렇지 않으면 경보와 정비가 다시 분리됩니다.
